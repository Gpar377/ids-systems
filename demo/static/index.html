Adversarial evasion vs. what the wire allows · SRM 21CSC302J · Topic 10

An adversarial example is only a threat if a real attacker can send it.

ML intrusion detectors are usually attacked by nudging all 41 NSL-KDD features freely. Over real TCP/IP an attacker controls only 9 of them. This lab measures how much of the threat survives when the attack is limited to what the wire allows, and compares the published IDS against our improved one.

How these numbers were measured

  • Honest protocol. Trained on KDDTrain+, tested on KDDTest+, which contains 17 attack types never seen in training. A random split of the training file scores ~99.8% because it tests on attacks the model has already seen.
  • Threshold. Our IDS's alarm threshold was chosen on validation data where whole attack types were held out of training. The test set was never used to pick it.
  • Evasion, not accuracy-under-attack. The attacker perturbs only their own attack traffic. Perturbing every test connection (the paper's protocol) mostly manufactures false alarms on normal users' traffic, which no attacker controls.
  • Every number on this page is read from results/*.csv, produced by python src/experiment.py.

Run the lab on a machine with Docker

The capture lab is an isolated Docker network: attacker, victim, a third-party host and a tcpdump sensor. It needs no internet once the images are built.

  1. Copy the project's lab/ folder to the Docker machine.
  2. Run bash run_capture.sh full inside it.
  3. Bring back lab/pcaps/capture.pcap and drop it here.

Content features (logged_in, num_root, …) are host state that never appears on the wire, so they are 0 in captured rows. That is itself the argument for why they are Class C.
